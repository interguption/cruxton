# PUBLISH-CRUXTON.md — build brief for Claude Code

**Goal:** turn this local `decision-records` method repo into **Cruxton** — a public GitHub repo that
anyone can install as a decision-records system across Claude Code, claude.ai, ChatGPT, Codex, Cursor,
and any other agent that reads a repo instruction file.

This brief is standalone. Work top-to-bottom; each phase leaves the repo shippable. Every structural
choice below is itself a decision — **file it as a record in `reports/` as you make it** (this repo
governs itself; the whole point is that publishing Cruxton is done *through* Cruxton). Regenerate the
index and commit at the end of each phase.

> (used in `marketplace.json`, `plugin.json` repository, README install commands). Placeholder below is

## 0. Naming — decided, apply verbatim

| Thing | Value | Note |
|---|---|---|
| Project / brand | **Cruxton** | front door only: README, repo, story |
| Installable skill id | **`cruxton-decision-records`** | what users install & trigger |
| Repo + plugin name | **`cruxton`** | `github.com/<GH>/cruxton` |
| Installed spec file | **`instructions/DECISION-RECORDS.md`** | **do not rename** — repos already cite this path |

Naming canon (Pranav's): exactly one front door carries the brand; identifiers underneath stay
descriptive so nothing citing them breaks. So: rename the *skill/plugin/repo*, but the files the
bootstrap drops into a target repo (`DECISION-RECORDS.md`, `decision_index.py`, `CLAUDE.md`,
`AGENTS.md`) stay descriptively named. Renaming the skill does **not** touch already-bootstrapped repos
(e.g. Steelyard) — they keep their descriptive files.

Constraint check (verified against current docs): skill `name` must be lowercase letters/numbers/hyphens,
≤64 chars, and must not contain the reserved words `anthropic` or `claude`. `cruxton-decision-records`
is valid.

```
│         ├─ AGENTS.md.template            ← NEW

├─ reports/                                ← genesis ledger — the method's own decisions (KEEP as-is)
├─ scripts/
│   └─ decision_index.py                   ← this repo's own working copy (generated by dogfooding, see below)
```

**Generator single-source rule.** Today `scripts/decision_index.py` and `templates/decision_index.py`
are byte-identical duplicates — a drift risk. Make `skills/cruxton-decision-records/templates/decision_index.py`
the canonical one. The repo's *own* `scripts/decision_index.py` should be produced by running the bundle's
bootstrap on this repo itself (dogfood), never hand-edited. If you change the generator, change the
template and re-bootstrap.


`claude-code-marketplace` are blocked), `owner.name`, and `plugins[]` each with `name` + `source`. The

```json
{
  "name": "cruxton",
  "owner": { "name": "Pranav", "url": "https://github.com/<GH>" },
  "plugins": [
    { "name": "cruxton-decision-records", "source": "./", "description": "Portable decision-records system." }

}
```
(If bundling ever grows to multiple plugins, switch `source` to per-plugin subfolders under `./plugins/`.)

## Phase 4 — Public polish & launch

1. **Rewrite `README.md` for strangers** (current one is author-facing). Include: a one-paragraph hero
   (what/why), the pace-layering picture, **one real example record** (copy a short `reports/DEC-*.md`),
   a per-tool **Install** section (Claude Code plugin · claude.ai zip · AGENTS.md tools · ChatGPT), and a

   the rails; humans can reconstruct the reasoning.
2. **`.github/workflows/validate.yml`** — on push/PR, `python3 scripts/decision_index.py` and fail the job
   on a bad record. This dogfoods the validator publicly (add a badge). Minimal:
   ```yaml
   name: validate-decision-records
   on: [push, pull_request]
   jobs:
     validate:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v5
           with: { python-version: "3.x" }
         - run: python3 scripts/decision_index.py
   ```
3. **`CONTRIBUTING.md`** — the method is *centrally mutable*: outsiders propose method changes via PR; any
   change to how the method works is itself a decision recorded in `reports/`; the method self-versions
   (`METHOD-VERSION` + `CHANGELOG.md`), and bootstrapped repos upgrade by re-running bootstrap.
4. **Ship:** regenerate the index, commit, create the public repo, push to `origin`, tag `v1.0.0`, cut a
   release with the zip asset.

**Record:** `DEC-ci-validates-on-push`. Then final `python3 scripts/decision_index.py` + commit.
